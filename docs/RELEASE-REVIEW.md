# Final delivery review — 19 October 2026

Decision: suitable for an employer demonstration and source-code review as a working portfolio commerce platform. This is a demonstration with fictional merchandise, simulated payments and Stripe test-mode support. It is not a verified live trading deployment.

The review covered source boundaries, dependency installation, build output, authentication, authorization, order ownership, pricing, discounts, inventory integrity, checkout, customer account data, admin CRUD, public pages, local assets, responsive layouts, runtime configuration, reverse proxy behavior and delivery contents. Existing development data was retained; automated journeys used disposable MongoDB replica sets.

Changes made during this review:

1. Added a public, typed checkout-options endpoint that exposes configured payment methods and demonstration shipping/tax policy without provider credentials. Checkout now hides unavailable providers, selects an available method, and handles configurations with no payment provider. Delivery prices also read that policy.
2. Corrected inventory search to match product names, product SKUs and variant SKUs, and corrected the displayed result cap.
3. Reset page descriptions during SPA navigation so a previous product description does not remain on account/information pages.
4. Fixed a zero comparison price rendering as stray text. Unknown sort and information-page keys such as `constructor` now fall back safely instead of reading inherited object properties.
5. Removed the editable but unused email field from account address editing; checkout retains its email field.
6. Corrected Nginx header inheritance and duplicate API headers, retaining appropriate caching and private API responses. Nginx only inherits parent `add_header` directives when the child scope does not declare its own; the revised configuration declares them consistently at server scope. See the [official header documentation](https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header).
7. Added bounded `TRUST_PROXY_HOPS`, defaulting to zero for direct local use and set to one in Compose for its private API behind Nginx. Tests prove that earlier spoofed forwarded hops do not change the rate-limit partition when the nearest client remains the same.
8. Expanded browser coverage for registration, guest-bag merging, wishlist persistence, profile/address changes, session restoration, account checkout, coupon errors, express shipping, provider availability, taxonomy CRUD, discount activation and route/asset/layout checks.

The nine browser journeys cover guest purchase and reload; admin product creation and audited stock adjustments; mobile filters and keyboard focus; denied access and logout; registration/account data and refresh restoration; account purchase with coupon/express delivery; unavailable/Stripe-only provider configuration; admin taxonomy/discounts/SKU search; and the route, asset and responsive audit. Provider-availability UI cases use an intercepted configuration response; they do not claim to complete a hosted Stripe payment.

Remaining boundaries for a live launch:

| Area                       | Status                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Actual payments            | Mock and Stripe test mode only. Hosted Stripe checkout with real test credentials was not exercised; signed webhook fixtures were. Live keys are intentionally rejected.                                                                                                                                                                                                               |
| Deployment                 | Linux Docker/Compose execution, public HTTPS, production cookie behavior behind a TLS terminator and a public host remain unverified. Windows Nginx and compiled-app verification do not replace that deployment check. The compiled preview uses test configuration with isolated data.                                                                                               |
| Operational services       | Email/password-reset delivery, physical fulfillment, tax integrations, general returns/refunds, monitoring, backups and disaster recovery are outside the implemented demo. Expiry currently runs in the API process.                                                                                                                                                                  |
| Concurrent cart writers    | Add/merge and full replacement currently use snapshots. Concurrent sessions modifying the same account can overwrite changes. Resolve with a deliberate atomic/versioned update policy before a live multi-session rollout.                                                                                                                                                            |
| Catalog and content        | Merchandise and seeded customers are fictional. Photography is licensed editorial placeholder imagery and is reused across products; accurate variant photography, content and real commercial policies are required for merchandising. Credits remain in `apps/web/public/images/SOURCES.md`.                                                                                         |
| Accessibility and browsers | Keyboard dialog dismissal/focus and semantic form labels are exercised. This is not a formal WCAG assessment. Automated browser runs use installed Chromium revision 1208; Firefox, Safari, current-browser installation and physical devices were not independently verified.                                                                                                         |
| SEO                        | Client-rendered metadata and structured data are implemented; server rendering/prerendering and social crawler validation remain future deployment work.                                                                                                                                                                                                                               |
| Maintenance                | The existing Mongoose reserved `collection` path warning remains. Clean install also reports the ESLint 9 support/deprecation notice; it has no reported npm vulnerability in this check, and upgrading the lint toolchain was left outside the delivery fix scope. Larger commerce/CSS modules and shared HTTP/domain utility coupling remain documented in `architecture-review.md`. |

For delivery, use the source archive in `deliverables/` and retain its SHA-256 file. The archive excludes dependency trees, local databases, downloaded tooling, test traces, real environment files and build output. It includes the lockfile, source, assets/credits, tests, configurations and handoff documentation. No code or message has been sent to any external recipient.
