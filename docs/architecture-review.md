# Architecture review — 19 October 2026

The later [release review](RELEASE-REVIEW.md) adds final delivery evidence, expanded tests and deployment corrections. The checks below record the earlier architecture-refactoring stage.

Reviewed the React features, shared UI, RTK Query ownership, Express routes, commerce and inventory rules, persistence models, contracts, dependencies, styles, and existing tests. Changes are limited to responsibility boundaries, actual duplication, and a measurable reduction in database requests. HTTP paths, DTOs, validation, status codes, pricing, authorization, and transaction behavior remain unchanged.

| Finding                                                                                                                        | Improvement                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admin imported product queries from the storefront router; queries depended on Express `Request`.                              | Both routers now call `modules/catalog/catalog.service.ts` with query values and pagination. The service has no Express dependency.                                                                                                                                   |
| Product creation, editing, reservation protection, inventory bounds, and stock auditing lived inside admin handlers.           | Moved these operations together into `modules/catalog/product.service.ts`, preserving MongoDB transaction boundaries and audit entries. The admin router decreased from 375 to 231 lines. Simple reads and CRUD remain inline where a wrapper would add little value. |
| Three cart mutations repeated hydration, projection, and persistence.                                                          | `saveCart` owns that sequence once. Validation and guest-merge modes retain their distinct behavior. The cart router decreased from 90 to 42 lines.                                                                                                                   |
| Shipping and tax values were independently declared in pricing and admin settings.                                             | Both now consume `commercePolicy`, preserving the existing integer-cent calculations.                                                                                                                                                                                 |
| Customer listing issued one order aggregation for every returned customer.                                                     | A grouped aggregation summarizes all customers on the page in one database call. Customer order counts still include all orders; spending still includes only paid orders. Detail responses use the same implementation.                                              |
| Checkout and payment endpoints belonged to the orders feature.                                                                 | The checkout feature now owns their injected endpoints. The orders API retains its existing exports and augmented API object for compatibility, using the same RTK Query base and endpoint names.                                                                     |
| Account and admin layouts implemented the same logout/cache-reset/navigation/error sequence.                                   | Authentication now owns `useSignOut`; both layouts consume it.                                                                                                                                                                                                        |
| Account address editing imported checkout's private form; catalog card and detail prices repeated markup and comparison logic. | Moved the unchanged address form into shared components and introduced a catalog-owned `ProductPrice`, preserving rendered structure and styling.                                                                                                                     |

No dependencies were added or removed. All declared web runtime packages have source consumers. API `tsx` is used by development and seed commands. Motion currently serves one hero entrance animation; replacing it with CSS could reduce the home bundle, but would require an explicit decision about animation behavior. Radix, form validation, Redux/RTK Query, and charting packages have distinct existing roles. There was no unused repository/service framework or duplicate state system worth introducing or removing.

The existing shared Button, Field, Dialog, DataTable, Pagination, error/loading/empty states, taxonomy editor, cart items, and order summary already provide useful reuse. Small forms with different schemas and mutation behavior remain separate. Central contracts and persistence declarations remain cohesive enough at their current size to retain their present organization.

Remaining architectural issues, in suggested order:

| Priority | Location                                                                       | Issue and next step                                                                                                                                                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Medium   | `apps/api/src/modules/carts/cart.routes.ts`                                    | Add/merge operations read a snapshot before writing the cart; simultaneous writers can overwrite one another. Resolve this with a deliberate concurrency policy, atomic operations or version checks, and parallel-request tests. This review preserves the current replacement semantics. |
| Medium   | `apps/api/src/modules/commerce.ts`                                             | Roughly 530 lines combine pricing, checkout creation, reservations, settlement, and fulfillment transitions. Separate these by transaction ownership when extending payment or fulfillment behavior; a mechanical file split alone would not establish that boundary.                      |
| Medium   | `apps/api/src/http.ts`, `modules/auth.ts`                                      | Domain services still import errors/validation/ID helpers from HTTP utilities, and commerce imports token hashing from the auth module that also defines routes. A small shared domain utility boundary would reduce that coupling in a future module separation.                          |
| Medium   | `apps/web/src/styles/storefront.css`, `features/admin/admin.css`               | Large global stylesheets (1,217 and 828 lines) rely on shared selectors and responsive cascade ordering. Feature-level style ownership is a useful next step, with visual coverage before moving rules.                                                                                    |
| Low      | `features/checkout/pages/CheckoutPage.tsx`, `features/account/AccountPage.tsx` | Checkout orchestration and account sections are still concentrated in their page modules. Extract cohesive sections or a checkout workflow hook when behavior grows; there is limited value in splitting only to reduce line counts.                                                       |
| Low      | `apps/api/src/models.ts`                                                       | Central schemas couple otherwise separate modules. The product `collection` field also triggers an existing Mongoose reserved-path warning. A domain schema split or persisted-field rename needs an explicit migration/compatibility plan.                                                |
| Low      | Storefront copy and checkout delivery labels                                   | Marketing/delivery text still embeds demonstration shipping amounts. Authoritative pricing and admin settings now agree through one policy; configurable shipping would also need a public policy contract for storefront messaging.                                                       |

Validation adds API coverage for admin draft filtering, all cart mutation paths, customer list/detail totals including unpaid and absent orders, and reservation-protected product edits. Browser journeys now also exercise customer and mobile-admin logout and protected-route denial afterward. Tests use isolated temporary MongoDB data; the existing local database and development server are preserved.

Completed checks: workspace typechecking, ESLint, Prettier, production builds for all three workspaces, 24 unit/API tests, four Chromium browser journeys, and the compiled API health/catalog smoke check. Browser tests used an ignored launcher/config copy on port 5174 because an existing Vite process occupied 5173, with the installed Chromium executable selected through `E2E_CHROMIUM_PATH`. Application code and test cases were unchanged by that port override. The existing Mongoose reserved-path warning remains visible.
